# GeoMap

GeoMap помогает изучать реки, озёра, горные массивы и их высшие точки на физической карте, страны и территории — на политической. На обеих картах можно выбрать часть света, Антарктиду или весь мир, а перед стартом тренировки задать количество заданий. На физической карте есть отдельный список объектов России. Ссылка на карту открывает «Изучение» в выбранной категории. Правила зачёта описаны в [спецификации](docs/product-spec.md).

## Локальный запуск

Установите Docker с плагином Compose и запустите Docker Engine. В корне проекта выполните:

```sh
docker compose up --build -d --wait
```

Документация API доступна на [localhost:8000/docs](http://localhost:8000/docs), проверка базы и API — на [localhost:8000/api/health](http://localhost:8000/api/health).

Установите Node.js 22.12+ и npm. В каталоге `frontend/` выполните:

```sh
npm ci
npm run dev
```

Откройте [физическую карту](http://localhost:5173/russia) или [политическую карту](http://localhost:5173/world). Vite проксирует `/api` на локальный FastAPI. При изменении `API_PORT` в корневом `.env` перезапустите Vite.

Для сборки в том же каталоге выполните `npm run build`. Сервер статики должен отдавать файлы из `frontend/dist/`, обслуживать `/russia` и `/world` через `index.html` и направлять запросы к `/api` в FastAPI.

Карта использует Leaflet. Рельеф физической карты хранится вместе с фронтендом в WebP и построен из [Natural Earth 1:50m, Cross-blended Hypsometric Tints](https://www.naturalearthdata.com/downloads/50m-raster-data/).

API при старте создаёт таблицы через SQLAlchemy Core и загружает список объектов из локальной выгрузки. PostgreSQL доступен контейнерам Compose и хранит данные в томе `pgdata`. Команда `docker compose down` останавливает сервисы и сохраняет том.

Для локальной разработки можно задать в файле `.env` переменные `API_PORT`, `CORS_ORIGINS` (через запятую) и `POSTGRES_PASSWORD`. Пароль из `.env` используется при создании базы в новом томе. Для разработки React по умолчанию разрешены `http://localhost:5173` и `http://127.0.0.1:5173`.

## Контракт для фронтенда

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/lists/russia` | Категории, физические объекты выбранной категории, параметры карты и атрибуция. Категория по умолчанию — `russia`. |
| `GET /api/maps/russia/reference-lines.geojson` | Береговые линии и границы. В свойствах каждого объекта указан `kind` со значением `coastline` или `boundary`. |
| `POST /api/lists/russia/training` | Старт тренировки и выдача первого задания. Пример тела — `{"name":"Анна","category":"europe","count":5}`. |
| `GET /api/lists/world` | Категории и контуры стран и территорий выбранной категории, столицы, данные для подсказок, параметры карты и атрибуция. Категория по умолчанию — `world`. |
| `POST /api/lists/world/training` | Старт тренировки на политической карте. Тело и формат ответа совпадают с физической картой. |
| `POST /api/training/{id}/tasks/{number}/answer` | Отправка координат и получение обратной связи. Повтор для того же номера возвращает сохранённую оценку и исходную точку. |
| `POST /api/training/{id}/tasks/{number}/next` | После ответа возвращает следующее `task` или финальный `result`. Повтор для уже пройденного номера возвращает текущее состояние. |
| `DELETE /api/training/{id}` | Удаление прохождения после подтверждения выхода. |

В запросах списка передавайте `?category=<id>`. Идентификаторы берутся из `categories`. Поле `available_count` задаёт максимум заданий, `training_count` — значение по умолчанию. В запросе старта можно опустить все поля. Для совместимости политическая карта при старте без категории и количества использует исходный набор из 12 стран.

Нумерация заданий начинается с 1. При ответе передавайте `{"longitude":31.5,"latitude":60.8}` в WGS84. Нормализуйте долготу клика к диапазону от −180° до 180°. Границы начального вида карты заданы в порядке запад, юг, восток, север.

При промахе `object_id` указывает на контур, который нужно показать, а `distance_label` содержит готовый текст, включая формат «Менее 0,1 км». При попадании поля расстояния равны `null`. Ответ до выдачи задания и переход до ответа получают HTTP 409. Для недоступного прохождения API возвращает HTTP 404.

Храните идентификатор прохождения в памяти страницы. При обновлении страницы снова загрузите «Изучение» по идентификатору списка. Для повтора создайте новое прохождение. Идентификатор прохождения даёт доступ к нему до удаления или истечения 24 часов. Сервер удаляет истёкшие записи при старте API и создании новых прохождений.

Поле `geometry` задаёт область зачёта. Волга и другие обзорные реки отображаются по `centerline`, Нева — по контуру акватории. У горного массива поле `summit` задаёт координаты и высоту вершины. Вершина имеет тот же контур зачёта, что и массив. Физическая карта показывает этот контур при наведении и после промаха. Показывайте атрибуцию из ответа API. См. [источники геоданных](backend/geomap/data/README.md).

## Проверки

Для браузерных проверок поднимите API и PostgreSQL через Compose. Затем из `frontend/` выполните:

```sh
npx playwright install chromium
npm test
```

Для HTTP-тестов с запущенными сервисами выполните в корне проекта:

```sh
docker compose run --rm --no-deps --user 0 --volume "./backend:/checks:ro" api sh -c 'pip install --no-cache-dir -q -r /checks/requirements-test.txt && GEOMAP_TEST_DB=1 python -m pytest -p no:cacheprovider /checks/tests'
```

Тесты проходят через HTTP-интерфейс FastAPI и создают отдельную схему PostgreSQL, которую удаляют после прогона.
