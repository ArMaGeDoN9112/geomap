# GeoMap

Сервер GeoMap отдаёт готовый список «Водоёмы России» с контурами 11 объектов и ведёт прохождение тренировки без регистрации. Правила зачёта описаны в [спецификации](docs/product-spec.md).

## Локальный запуск

Установите Docker с плагином Compose и запустите Docker Engine. В корне проекта выполните:

```sh
docker compose up --build -d --wait
```

Документация API доступна на [localhost:8000/docs](http://localhost:8000/docs), проверка базы и API — на [localhost:8000/api/health](http://localhost:8000/api/health).

API при старте создаёт таблицы через SQLAlchemy Core и загружает список объектов из локальной выгрузки. PostgreSQL доступен контейнерам Compose и хранит данные в томе `pgdata`. Команда `docker compose down` останавливает сервисы и сохраняет том.

Для локальной разработки можно задать в файле `.env` переменные `API_PORT`, `CORS_ORIGINS` (через запятую) и `POSTGRES_PASSWORD`. Пароль из `.env` используется при создании базы в новом томе. Для разработки React по умолчанию разрешены `http://localhost:5173` и `http://127.0.0.1:5173`.

## Контракт для фронтенда

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/lists/russia` | Готовый список, контуры GeoJSON, параметры карты и атрибуция. Стабильный идентификатор списка для ссылки учителя — `russia`. |
| `GET /api/maps/russia/reference-lines.geojson` | Береговые линии и границы. В свойствах каждого объекта указан `kind` со значением `coastline` или `boundary`. |
| `POST /api/lists/russia/training` | Старт новой тренировки и выдача первого задания. Тело можно опустить или передать `{"name":"Анна"}`. |
| `POST /api/training/{id}/tasks/{number}/answer` | Отправка координат и получение обратной связи. Повтор для того же номера возвращает сохранённую оценку и исходную точку. |
| `POST /api/training/{id}/tasks/{number}/next` | После ответа возвращает следующее `task` или финальный `result`. Повтор для уже пройденного номера возвращает текущее состояние. |
| `DELETE /api/training/{id}` | Удаление прохождения после подтверждения выхода. |

Нумерация заданий начинается с 1. При ответе передавайте `{"longitude":31.5,"latitude":60.8}` в WGS84. Нормализуйте долготу клика к диапазону от −180° до 180°. Границы начального вида карты заданы как запад, юг, восток, север и проходят через 180-й меридиан.

При промахе `object_id` указывает на контур, который нужно показать, а `distance_label` содержит готовый текст, включая формат «Менее 0,1 км». При попадании поля расстояния равны `null`. Ответ до выдачи задания и переход до ответа получают HTTP 409. Для недоступного прохождения API возвращает HTTP 404.

Храните идентификатор прохождения в памяти страницы. При обновлении страницы снова загрузите «Изучение» по идентификатору списка. Для повтора создайте новое прохождение. Идентификатор прохождения даёт доступ к нему до удаления или истечения 24 часов. Сервер удаляет истёкшие записи при старте API и создании новых прохождений.

Контуры из списка подходят для отображения акваторий, подсветки и обратной связи. Слой акваторий нужен и при выключенной подсветке, чтобы ученик видел русло Невы. Клиент выбирает, когда показывать названия. Рельеф использует внешний сервис тайлов Esri, а береговые линии и границы отдаются самим API. Показывайте атрибуцию из ответа API. См. [источники геоданных](backend/geomap/data/README.md).

## Проверки

С запущенными сервисами выполните в корне проекта:

```sh
docker compose run --rm --no-deps --user 0 --volume "./backend:/checks:ro" api sh -c 'pip install --no-cache-dir -q -r /checks/requirements-test.txt && GEOMAP_TEST_DB=1 python -m pytest -p no:cacheprovider /checks/tests'
```

Тесты проходят через HTTP-интерфейс FastAPI и создают отдельную схему PostgreSQL, которую удаляют после прогона.
